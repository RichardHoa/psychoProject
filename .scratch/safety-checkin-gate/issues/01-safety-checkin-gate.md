# 01: Safety check-in gate before entering the site

**What to build:** The full end-to-end feature from the spec: gate decision logic, the `/kiem-tra-an-toan` chat-bubble gate page, and site-wide session interception so any fresh navigation to any route (including deep links) is routed through the gate first, with the answer honored and the gate skipped for the rest of that browser session.

**Blocked by:** None (can start immediately)

**Status:** implemented

**Implementation notes (scope evolved during review with the user):** the "Yes → in hours" auto-connect and the "Go anyway" / "skip wait" buttons now open the hotline (`https://duongdaynongngaymai.vn/`) in a **new tab** (`window.open(..., '_blank', 'noopener,noreferrer')`) rather than navigating the current tab away, per a later user request — the gate page itself stays open behind it. Bot chat bubbles show a single static `CatMascot` pose each (no looping wave animation while "talking"), with a distinct pose per bubble (waving hello on the intro, a different pose on the question, etc.), and all `CatMascot` instances on this page (header + every bubble avatar) are sized `h-11 w-11` to match the navbar cat icon used on other pages. The header cat on this page is deliberately left non-clickable (unlike other pages' navbar cat, which navigates home on click) — the user confirmed this choice, since a one-click way home would let a visitor skip the safety question before answering it, and the gate only re-triggers on a fresh browser session, not on a client-side navigation. A code-review pass also caught and fixed a real bug in `CatMascot.svelte` unrelated to this ticket's own code: its `autoplay` effect implicitly depended on internal animation state and looped forever instead of settling — fixed with `untrack()`.

- [x] `getHotlineStatus(now)` (`src/lib/safety/hotlineStatus.js`) returns whether a given `Date` falls inside the hotline hours window: 13:00–20:30, Wednesday through Sunday, evaluated in the `Asia/Ho_Chi_Minh` timezone regardless of the host machine's local timezone.
- [x] `getHotlineStatus` has vitest tests (`hotlineStatus.test.js`) covering: a time inside the window on a valid day, a time before opening and a time after closing on a valid day, and a day the hotline doesn't operate (Monday).
- [x] `resolveGateDestination(url)` (`src/lib/safety/gateDestination.js`) computes the redirect target from an originally requested URL, preserving the full path and query string unchanged, with vitest tests (`gateDestination.test.js`) covering a bare root/landing request and a deep-link request carrying query params.
- [x] The gate page at `/kiem-tra-an-toan` reveals message bubbles in sequence: intro copy briefly explaining what MÈO does (placeholder Vietnamese copy, flagged in-code as needing content review), then a question bubble with the exact text "Bạn đang có ý định làm hại bản thân không?" and Yes/No buttons.
- [x] Answering "No" shows a short, warm acknowledgment bubble for about 2 seconds, then automatically navigates to the visitor's originally requested destination.
- [x] Answering "Yes" checks `getHotlineStatus(now)` server-side (computed in `+page.server.js`'s `load()`) and branches:
  - [x] In hours: the next bubble shows a countdown and opens the hotline in a new tab at zero (see implementation note above re: new tab vs. same-tab navigate); a manual button lets the visitor skip the wait and go immediately.
  - [x] Off hours: the next bubble states plainly that the hotline isn't staffed right now, with a manual "Go anyway" button opening the hotline, no auto-countdown, and no separate resource list.
- [x] All bubbles for a given path render within the same chat thread/page, not a separate screen.
- [x] On the first navigation of a browser session to any route, the visitor is redirected to the gate page first (`src/routes/+layout.svelte`, `onMount`), with the originally requested full path + query string captured as the gate's destination.
- [x] After the gate is answered (either path), the "session answered" state is recorded client-side (`sessionStorage`, `src/lib/safety/gateSession.js`) so subsequent navigations within the same browser session do not redirect through the gate again; the gate page itself also checks this on mount so browser Back doesn't replay the question.
- [x] A new browser session (tab/browser closed and reopened) triggers the gate again — this follows directly from using `sessionStorage`.
- [x] The "No" path lands the visitor exactly on the originally requested URL (path + query string intact) when a deep link was requested.
- [~] **Not run by the agent:** the manual-verification checklist (fresh landing load, fresh deep-link load, no re-gate on second nav, Yes path for both in-hours and off-hours) was not walked end-to-end in a browser, per this project's standing instruction that the agent never starts the dev server itself. The intro/question stage and the mascot sizing were confirmed against a screenshot the user provided; the remaining flows (No-path redirect, both Yes branches, deep-link preservation, session persistence) still need a manual pass — ask if you'd like a walkthrough script for that.
